# GitHub repositories that could strengthen Coronary Atlas

Reviewed 9 October 2026 against the current 55-input app, saved model experiments, AngioCAD transport test, and reference-anatomy viewer. This is a targeted repository search, not a complete GitHub census. Repository benchmark numbers are not comparable to our nested out-of-fold estimates without the same patients, labels, splits and fitting rules. No third-party code or anatomy was copied into the app for this review.

| Repository and source | Concrete value here | Decision and boundary |
|---|---|---|
| [InterpretML / Explainable Boosting Machine](https://github.com/interpretml/interpret) ([EBM API](https://interpret.ml/docs/python/api/ExplainableBoostingClassifier.html), MIT code) | A distinct additive model family for mixed tabular inputs, with model-native local terms. We ran a fixed no-interaction configuration on the saved 303-person outer folds. | **Completed research trial:** [protocol, results and audit](ebm_github_trial.md). CAD mean AUROC rose from .9098 to .9285 and Brier fell from .1045 to .0930; LAD AUROC was flat, while LCX and RCA worsened. These are reused-patient development results after prior model searches. Explanation reconstruction and independent CAD validation remain open. Keep default models unchanged. |
| [Evidently](https://github.com/evidentlyai/evidently) ([drift preset](https://github.com/evidentlyai/evidently/blob/main/src/evidently/presets/drift.py), Apache 2.0) | An offline, reproducible report of distributions and missingness for the **13 mapped** source and AngioCAD inputs could make the new-population comparison easier to inspect. | **Useful optional evidence, not an accuracy fix.** Review each source/external code and unit first; report sample sizes and descriptive shifts. Its automated drift flag would not validate the served 55-input app or explain causally why performance changed. |
| [Human Atlas](https://github.com/ashemag/human-atlas) ([anatomy attribution](https://github.com/ashemag/human-atlas/blob/main/public/ATTRIBUTION.md), MIT viewer code; BodyParts3D CC BY 4.0) and [AAS](https://github.com/Kehn-Marv/AAS) | Compare vessel selection, loading, keyboard/mobile flows, reference labels and lesson pacing with other open anatomy viewers. | [ImageCAS-X](https://github.com/kitbransby/ImageCAS-X) | A research benchmark with coronary vessel labels and surfaces from 800 CCTA scans, including LAD, LCx and RCA. | [Fairlearn](https://github.com/fairlearn/fairlearn) (MIT) | Subgroup error tables with denominators could test whether sex/age patterns are being hidden by pooled metrics. | **Conditional follow-up.** Verify code meanings and link rows to the local workbooks; small or single-class groups must be suppressed. ## Submission decision

The strongest immediate GitHub contribution was methodological: the locked EBM trial found a promising CAD-only research signal, while open anatomy projects sharpened the reviewer checklist and demo positioning. The trial did not produce a general four-target improvement. An additional repository cannot create new independent patients or repair undocumented feature timing/units. The strongest remaining evidence would still be a compatible untouched cohort, the one qualified coronary review, and an observed user task. Pitch the distinctive *linked held-out error, separate live explanation, and transparent population-transfer evidence* rather than claiming novelty for a 3D heart or a quiz.

## Follow-through: external population and native EBM terms

The [next accuracy step](peerj_external_results.md) is complete: on 553 new Chinese patients, a separate 14-input source-only EBM did not beat its matched logistic comparator (AUC .664 vs .674; Brier .333 vs .307). EBM native terms reconstructed all 303 source and 553 external outputs, but this explanation-fidelity check does not establish predictive validity and does not cover the 55-input candidate. The official PeerJ/PMC supplement was acquired instead of a GitHub mirror containing 162 duplicate rows and altered values. No app-model replacement follows from this trial. The open-source family was useful to test a hypothesis; the result limits the claim we can make.
